Retrieves the authenticated user's own account data from the X API v2 endpoint GET /2/users/me. Invoke via `node <base_directory>/x.ts me [flags]`. Output is JSON to stdout.

[!FLAGS] a) no flags — returns the authenticated user with a sensible default set of profile fields (identity, bio, metrics, verification, avatar, dates, DM accessibility, relationship status). b) `--fields <comma-separated-list>` — request ONLY the specified fields instead of defaults. c) `--pinned-tweet` — adds the pinned post to the user as `pinned_tweet`, in place of `pinned_tweet_id`, looked up as `get` does. X's own `pinned_tweet_id` expansion answers "Not Found" for pinned posts that exist, so the post costs a second request. No `pinned_tweet` means no pinned post.

[!AVAILABLE-FIELDS] The `--fields` flag accepts any combination of: `id`, `name`, `username`, `description`, `created_at`, `location`, `url`, `profile_image_url`, `protected`, `public_metrics`, `verified_type`, `connection_status`, `receives_your_dm`, `pinned_tweet_id`, `most_recent_tweet_id`, `entities`, `withheld`, `affiliation`, `is_identity_verified`, `subscription_type`. The default set (when no `--fields` is given) includes: `created_at`, `description`, `id`, `name`, `profile_image_url`, `public_metrics`, `username`, `verified_type`, `connection_status`, `location`, `protected`, `receives_your_dm`, `url`.

[!OUTPUT-SHAPE] `data` is the user object with the requested fields, plus `pinned_tweet` with `--pinned-tweet`.
